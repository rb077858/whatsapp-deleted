# אל-מחיק 🧽

בוט וואטסאפ (Baileys) ששומר עותק של הודעות מקבוצות וצ'אטים נבחרים, ומתריע כשמישהו מוחק או עורך הודעה.
רץ 24/7 על טלפון אנדרואיד דרך **Run on Phone**. הממשק הציבורי יושב ב-**Firebase Hosting**, ומדבר עם הטלפון דרך **Firestore**, כך שלא צריך מנהרה או כתובת ציבורית לטלפון.

```
דפדפן (Firebase Hosting)  ──►  Firestore (rpc / joins)  ◄──  הטלפון (Node + Baileys)
```

## איך זה עובד למשתמש
1. **הצטרפות** באתר: במחשב מוצג ברקוד, ובטלפון קוד חיבור לפי מספר טלפון. במצב "קוד הזמנה" צריך להזין קוד מעל כפתור ההצטרפות.
2. **הניהול כולו באתר** (`/app`): בוחרים מה לגבות, משנים הגדרות, משתפים ומאשרים בקשות. לכל צ'אט שנבחר נוצרת קבוצה `<שם> (הודעות)`, וכל הודעה מועתקת אליה עם שם השולח.
3. **📣 קבוצת עדכונים** ("אל-מחיק 🧽 · עדכונים"): נוצרת אוטומטית לכל משתמש. מגיעים אליה בקשות הצטרפות (עם קישורים לאישור ולדחייה), הצטרפויות דרך קישור, קודי כניסה והודעות מהצוות.
   - **אסור לכתוב בה.** הקבוצה נוצרת מהחשבון של המשתמש, ולכן וואטסאפ לא יכול למנוע ממנו לכתוב. במקום זה, כל הודעה שהוא כותב שם (טקסט, מדיה, סטיקר) חוסמת את החשבון ועוצרת את הגיבוי. תגובות, מחיקות ועריכות לא נחשבות. המנהל יכול לבטל את החסימה, וגם לחסום ידנית.
   - אם המשתמש מחק את הקבוצה או יצא ממנה, תיווצר קבוצה חדשה בחיבור הבא.
4. **כניסה** לממשק ממכשיר חדש: מזינים מספר טלפון, והקוד בן 6 הספרות נשלח לקבוצת העדכונים.
5. **ניהול** (`/admin`): מצב הרשמה, משתמשים, שירות לקוחות (כולל חסימה וביטול חסימה), והודעה לכל המשתמשים או למשתמש מסוים בקבוצת העדכונים.
   ברירת המחדל: הרשמה עם קוד הזמנה `123456`, ומשתמש מנהל `rb077858`.

אין קבוצת ניהול שכותבים בה פקודות: הניהול כולו באתר. משתמשים שהייתה להם קבוצת "אל-מחיק 🧽" הישנה מקבלים בה הודעה אחרונה, ומאז הבוט לא משתמש בה.

## הקמה (פעם אחת)
1. **פרויקט Firebase חדש** (מומלץ פרויקט נפרד מזה של Run on Phone, כדי שה-rules לא ידרסו זה את זה):
   - Build ← **Firestore Database** ← Create
2. **פריסת האתר והחוקים** מהמחשב:
   ```
   npm i -g firebase-tools
   firebase login
   firebase use --add        # לבחור את הפרויקט החדש
   firebase deploy --only hosting,firestore
   ```
   האתר יהיה ב-`https://<project-id>.web.app`.
3. **פרסום לטלפון**: `node "C:\Projects\AAA\run-on-phone\publisher\publish.mjs" "<נתיב הפרויקט>"`
4. בטלפון, באפליקציה, לוחצים על הכפתור **"הגדרת שרת"** ומעלים את קובץ ה-service account
   (Firebase Console ← Project settings ← Service accounts ← Generate new private key).
   הקובץ נשמר רק ב-`DATA_DIR` בטלפון.
5. (רשות) משתנה `SITE_URL` ב-`run-on-phone.json` ← `env`, אם יש לכם דומיין משלכם. הוא משמש בקישור שהבוט שולח בפקודה `ממשק`.
   אם לא מגדירים אותו, הבוט עדיין מגיע לאתר בכתובת `https://<project-id>.web.app`.

## הרצה מקומית
```
npm install
npm run dev     # PORT=3101 DATA_DIR=./.phone-data
```
אפשר גם `DATA_DIR=./.phone-data` עם service account ב-`.phone-data/firebase-service-account.json`.

## מבנה
| קובץ | תפקיד |
|---|---|
| `src/index.js` | עלייה, כיבוי מסודר ב-SIGTERM |
| `src/manager.js` | ניהול כל חיבורי הוואטסאפ + תהליך ההצטרפות (QR / קוד) |
| `src/bot.js` | חיבור של משתמש אחד: קבוצת ניהול, גיבוי הודעות, התראות מחיקה/עריכה |
| `src/api.js` | פעולות הממשק (כניסה, דשבורד, ניהול) |
| `src/relay.js` | האזנה ל-Firestore, heartbeat וניקוי |
| `src/http.js` | שרת מקומי על `PORT`: האתר + `/setup` |
| `src/db.js` | SQLite מובנה (`node:sqlite`) ב-`DATA_DIR` |
| `web/` | האתר (עובד גם ב-Firebase Hosting וגם מקומית) |

## הערות
- בלי תוספות native: `sharp` לא מותקן (`.npmrc` → `legacy-peer-deps`), ולמדיה משתמשים בתמונה הממוזערת המקורית.
- מדיה נשמרת לקובץ זמני ב-`DATA_DIR/tmp` ונשלחת משם, כך שלא נטען הכל לזיכרון. ברירת המחדל לגודל מקסימלי היא 50MB.
- כל חיבור וואטסאפ צורך זיכרון. בטלפון כדאי להשאיר תקרה סבירה של משתמשים.

## הגנות על הטלפון
- **גודל קובץ מקסימלי**: ברירת המחדל היא 16MB. המנהל קובע תקרה לכולם, וכל משתמש יכול לבחור מגבלה נמוכה יותר.
- **קצב**: עד 10 קבצים לדקה לכל משתמש (ניתן לשינוי בניהול). קבצים מעבר לזה לא מגובים, ובמקומם נשלחת הודעה עם שם השולח.
- **מקביליות**: לכל היותר 2 הורדות או העלאות של קבצים בו-זמנית, בכל השרת.
- **זיכרון**: מד זיכרון בעמוד הניהול. ב-85% מהתקרה גיבוי הקבצים מושהה זמנית, וטקסט ממשיך להתגבות.
- **חיבור יציב**: לכל בקשה מהאתר יש מגבלת זמן. אם החיבור נתקע, האתר עובר לחיבור long-polling. בצד השרת יש watchdog שמזהה האזנה תקועה ומחבר אותה מחדש.

## בלי כתיבת נתוני סנכרון
הבוט לא כותב נתוני סנכרון (app-state) של וואטסאפ: לא רשימות, לא השתקה ולא ארכיון. כתיבה כזו מבחוץ, כשהיא לא תואמת בדיוק את מה שיש בטלפון, גורמת לוואטסאפ לנתק את כל המכשירים המקושרים.

## חיבור מחדש
- **המשתמש:** כשהוואטסאפ מתנתק, בממשק מופיע "🔌 חיבור מחדש". זה לא דורש קוד הזמנה, ואותו חשבון ממשיך עם כל הגיבויים.
- **המנהל:** בכרטיס המשתמש יש "🔌 חיבור מחדש בקוד". הוא מייצר קוד בן 8 תווים, ואפשר לשלוח אותו למשתמש בוואטסאפ בלחיצה. הסטטוס מתעדכן ברגע שהמשתמש מתחבר.
- **מחיקת חשבון:** המשתמש יכול למחוק את החשבון מהממשק. זה מנתק את הוואטסאפ ומוחק את כל הנתונים שלו מהשרת.
